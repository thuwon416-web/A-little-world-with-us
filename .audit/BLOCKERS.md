# Deployment blockers requiring human action

1. **Staging access not available in this run.** No staging base URL, test user tokens, staging couple ID, orphaned Drive file ID, or staging-only Guardian test route was provided. No staging endpoint was called and no Production endpoint was called. Use `scripts/smoke-test-staging.ts` after staging is available; checks with missing staging inputs are skipped explicitly.
2. **Resend credentials are not configured by this code change.** Ops must add `EMAIL_PROVIDER=resend`, `RESEND_API_KEY`, and `EMERGENCY_EMAIL_FROM` to the staging Supabase Edge Function environment and verify sender-domain status. The email test script was created but deliberately not executed.
3. **Database migrations remain unapplied.** The four SQL migrations are files only. Apply them to staging first, validate, back up Production, then apply to Production in filename order only after human approval.
4. **Backblaze key scope remains an operational requirement.** The application still uses direct browser uploads with a temporary bucket upload token. The signed metadata and verify endpoint prevent unverified references being persisted, but do not make B2 enforce the HMAC. Ops must restrict the Backblaze Application Key to the intended bucket and `couples/` prefix; a server-side proxy remains the stronger future hardening option.
5. **Guardian test route is not present in the repository.** The smoke script supports a separately deployed staging-only `STAGING_GUARDIAN_TEST_URL`, but no new privileged test route was added to the application. Use the documented manual test after seeding a controlled staging memory.

6. **Cron smoke check is intentionally opt-in.** The existing `/api/cron/check-geofence` route uses GET and invokes a mutating Edge Function. The smoke script skips it unless `STAGING_ALLOW_CRON_SIDE_EFFECTS=true` is explicitly set for disposable staging; it does not call a cron endpoint by default.
