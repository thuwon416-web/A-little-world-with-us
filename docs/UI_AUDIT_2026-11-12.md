## Findings and changes made

### Theme and contrast
- Corrected the light/dark color-scheme mapping so Lavender, Peach, Mint, and Ocean use light native controls; only Monochrome uses dark controls.
- Synced the web CSS palette with the shared theme tokens and aligned the mobile theme tokens.
- Darkened muted labels, accent text, and semantic success/warning/error colors to meet at least 4.5:1 contrast against the corresponding theme background/card surfaces in the checked palette values.
- Made primary button foreground colors theme-aware; fixed mobile secondary-button text contrast.
- Removed a hard-coded pink accent from the mobile dashboard and made the days-together banner follow the selected theme.
- Removed the fixed purple shadow from shared card surfaces.

### Layout and component consistency
- Added a 24px default padding baseline for web glass cards while allowing explicit Tailwind padding utilities to override it.
- Standardized the mobile shared card primitive at 20px padding and 20px radius; aligned mobile dashboard memory/stats cards to that baseline.
- Restricted card hover lift to devices with a real hover pointer and removed the global lift from every button.
- Raised legacy 9–11px web labels and the audited mobile wellness-board labels to a 12px floor.
- Added a 44px minimum height to the legacy mobile button.

### Typography and language
- Fixed the web font-variable mismatch and retained a Myanmar-capable font fallback.
- Updated the document language attribute when the selected web locale changes.
- Filled missing sidebar navigation translations and localized sidebar group labels and accessibility names.
- Localized the web and mobile dashboards, memory/stat panels, love-streak controls, anniversary share card, and the web Wellness page's primary controls and workout labels.
- Kept user-authored memory content in its original language.

### Mobile reliability/accessibility
- Matched the mobile status bar to the selected theme brightness.
- Moved the mobile error boundary inside the Theme and I18n providers so its fallback can safely use those contexts.
- Localized mobile error and stack-header labels.
